# Firefight 模组包格式

版本 0.1.0

## 1. 引言

### 1.1 目的

本文定义一个用于分发 Firefight 模组的包格式：单个归档承载可直接进游戏的载荷、机器可读的元数据，以及可选的人工文档。

### 1.2 范围

该格式规定模组包包含什么、读取方如何读取。它不定义游戏自身的内容格式；载荷由游戏已经能够读取的文件组成。

该格式独立于任何游戏版本。包在其元数据中声明所针对的游戏版本，因此一个格式服务于所有版本。

### 1.3 读者

制作者写出包：模组编辑器、构建脚本，以及手工打包的作者。读取方读取包：游戏内模组管理器，以及任何检查或安装模组的工具。

## 2. 一致性

### 2.1 要求关键词

关键词 MUST、MUST NOT、REQUIRED、SHALL、SHALL NOT、SHOULD、SHOULD NOT、RECOMMENDED、MAY、OPTIONAL 按 RFC 2119 的描述解释。

### 2.2 一致的包

包满足第 3 至第 8 节的全部 MUST 与 MUST NOT 即为一致。

### 2.3 一致的读取方

读取方满足第 9 节的全部 MUST 与 MUST NOT，并按第 10 节对其中列出的每种情形给出该节规定的判定，即为一致。

制作者与读取方彼此独立；一个包可以是一致的，而尚不存在与之对应的合格读取方。

## 3. 术语

| 术语 | 定义 |
| --- | --- |
| 包 | 承载一个模组的单个归档。 |
| 载荷 | 读取方安装的文件树。 |
| 载荷根 | 归档内承载载荷的目录。 |
| 读取方 | 读取包的软件。 |
| 制作者 | 写出包的软件或人。 |
| 旧版包 | 没有元数据文件的包，即本文发布之前产生的包。 |
| 格式版本 | 包内声明的整数 `spec_version`。 |
| 文档版本 | 本文自身的语义化版本，记于 `CHANGELOG.md`。 |

## 4. 包

### 4.1 归档

包是 ZIP 归档。

- 制作者应使用 `.ffmod` 扩展名命名文件。
- 读取方必须同时接受 `.ffmod` 与 `.zip`，不论实际扩展名为何。
- 压缩方式可为 deflate 或存储。

### 4.2 条目名

归档内的条目名是相对路径。

- 制作者必须以正斜杠 `/` 分隔路径段。
- 读取方必须把反斜杠 `\` 视为等价分隔符，因为在某些平台上写出的归档含该字符。
- 条目名不得为绝对路径，不得含 `..` 路径段，不得含盘符。
- 单个路径段不得超过 255 字节。
- 条目违反上述规则时，读取方必须拒绝整个归档，不得跳过该条目。

### 4.3 顶层条目

| 路径 | 要求 | 作用 |
| --- | --- | --- |
| `Mod/` | 必需 | 载荷，见第 5 节。 |
| `Mod_Information.toml` | 必需 | 元数据，见第 6 节。 |
| `README.md` | 建议 | 面向解包阅读者的说明，见第 8 节。 |
| `LICENSE` | 建议；重新分发第三方资源时为必需 | 许可证原文，见第 8 节。 |
| `DOCS/` | 可选 | 文档页，见第 7 节。 |

制作者不得在归档根再放第二份载荷树。读取方必须忽略本表以外的顶层条目，且不得因其存在而报错。

### 4.4 示例

```
<名称>.ffmod
├── Mod/
│   ├── Data/
│   ├── Images/
│   ├── Sounds/
│   └── mod.txt
├── README.md
├── Mod_Information.toml
├── LICENSE
└── DOCS/
    ├── About.md
    └── About_zh.md
```

## 5. 载荷

载荷根是归档根的 `Mod/` 条目。读取方安装后，载荷内容即成为游戏模组目录的内容。

- `Mod/mod.txt` 必须存在，且必须是普通文件。
- `Mod/mod.txt` 保持游戏所读取的格式。本文不重新定义该格式。读取方可读取其 `<name>` 标签用于展示；标签缺失时必须回退到元数据。
- `Mod/Data/`、`Mod/Images/`、`Mod/Sounds/` 可任意组合出现。
- 载荷内的路径相对于载荷根。
- 载荷内不得出现嵌套的 `Mod/` 目录。

载荷以游戏自身的格式承载文件。制作者的工作文件，例如需编译进载荷的配置源文件，不属于载荷。

## 6. 元数据

### 6.1 位置与编码

元数据文件为 TOML v1.0，以 UTF-8 编码且不带字节序标记。它位于归档根、载荷之旁。

### 6.2 文件名

- 制作者必须把文件命名为 `Mod_Information.toml`。
- 读取方必须同时接受不带下划线的 `ModInformation.toml`；两者同时存在时以带下划线者为准。

### 6.3 字段

| 字段 | 类型 | 要求 | 含义 |
| --- | --- | --- | --- |
| `spec_version` | 整数 | 必需 | 该包遵循的格式版本。本文定义版本 `1`。 |
| `name` | 字符串 | 必需 | 展示名，1 至 64 个字符。 |
| `version_name` | 字符串 | 必需 | 模组版本，形如 `X.Y.Z`，十进制数字，无前导零。 |
| `version_code` | 整数 | 必需 | 非负整数，用于排列同一模组的各次发布。 |
| `game_version` | 字符串 | 必需 | 载荷针对的游戏版本，例如 `"13.2.0"`。 |
| `authors` | 字符串数组 | 必需 | 一位或多位作者名。 |
| `id` | 字符串 | 可选 | 稳定标识，匹配 `[a-z0-9._-]{1,64}`。 |
| `update_code` | 整数 | 可选 | 由制作者定义的整数，用于表示更新；缺省为 `0`。 |
| `license` | 字符串 | 可选 | SPDX 许可证标识，例如 `"MIT"`。 |
| `description` | 字符串 | 可选 | 单行纯文本，不超过 200 个字符。 |
| `homepage` | 字符串 | 可选 | 绝对 `https` URL。 |
| `docs` | 表数组 | 可选 | 文档页索引，见第 7.3 节。 |

读取方必须忽略自己不认识的字段。读取方不得因某个可选字段缺失而拒绝该包。

`id` 缺失时，读取方以 `name` 加归档文件名标识该模组。

### 6.4 示例

```toml
spec_version = 1
id = "example-overhaul"
name = "Example Overhaul"
version_name = "1.0.0"
version_code = 1
update_code = 0
game_version = "13.2.0"
authors = ["Example Author"]
license = "MIT"
description = "Replaces unit equipment tables."
homepage = "https://example.invalid/overhaul"

[[docs]]
file = "DOCS/About.md"
lang = "en"
title = "About"

[[docs]]
file = "DOCS/About_zh.md"
lang = "zh"
title = "关于"
```

## 7. 文档目录

`DOCS/` 存放面向读者的 Markdown 页面。页面以 UTF-8 编码，扩展名为 `.md`。

### 7.1 文件名

| 形式 | 作用 |
| --- | --- |
| `<stem>.md` | 不带语言标记的页面，视为默认页。 |
| `<stem>_<lang>.md` | 本地化为 `<lang>` 的页面。 |

`<lang>` 是小写 ISO 639-1 语言码，可再接 `-` 与大写 ISO 3166-1 alpha-2 地区码，例如 `zh` 或 `zh-CN`。`<stem>` 匹配 `[A-Za-z0-9_-]{1,64}`。

### 7.2 解析顺序

读取方需要某一指定语言的页面时，必须按以下顺序尝试，并采用第一个存在的文件：

1. `<stem>_<lang>-<REGION>.md`
2. `<stem>_<lang>.md`
3. `<stem>.md`

三者都不存在时，该页面视为缺失。读取方不得回退到其他 stem 的页面。

### 7.3 索引

`docs` 数组列出读取方应优先呈现的页面。每个条目接受：

| 字段 | 类型 | 要求 | 含义 |
| --- | --- | --- | --- |
| `file` | 字符串 | 必需 | 相对于归档根的路径，例如 `DOCS/About.md`。 |
| `lang` | 字符串 | 建议 | 该页面的语言标记。 |
| `title` | 字符串 | 可选 | 展示标题；缺省取文件名主干。 |

存在于 `DOCS/` 但未进入索引的页面同样有效、可读。

## 8. 说明文件与许可证

`README.md` 是写给在游戏之外解包阅读者的 Markdown 文本，应说明该模组改动了什么、针对哪个游戏版本、如何安装。它不得成为读取方所需信息的唯一存放处；元数据属于元数据文件。

`LICENSE` 存放适用于包内容的许可证原文。当 `license` 字段存在时，其 SPDX 标识必须与 `LICENSE` 的原文一致。

## 9. 导入流程

一致的读取方按顺序执行以下步骤。

1. 打开归档。条目名违反第 4.2 节时拒绝该归档。
2. 读取 `Mod_Information.toml`；不存在时按第 6.2 节读取 `ModInformation.toml`。
3. 两者都不存在时，按旧版包处理：定位直接包含 `mod.txt` 的最浅目录，作为载荷根。
4. 确定载荷根：存在 `Mod/` 条目时取该项；否则取直接包含 `mod.txt` 的最浅目录。若同一深度有两个目录都含 `mod.txt`，停止导入并报告该包歧义。
5. 按第 10 节校验元数据。出现错误时拒绝该包；出现警告时导入并记录该情形。
6. 只复制载荷。读取方不得把 `Mod_Information.toml`、`README.md`、`LICENSE` 或 `DOCS/` 复制进游戏的模组目录。
7. 在读取方自己的库中保留元数据与文档：有 `id` 时以 `id` 为键，否则以归档文件名为键。静默丢弃不被允许；无法保存时必须报告。
8. 记录已安装的 `version_name` 与 `version_code`，供后续包与之比较。

读取方不得在导入过程中修改载荷。能够停用已安装模组的读取方必须保持载荷原样，把停用状态表示在载荷之外。

## 10. 校验

| 情形 | 判定 |
| --- | --- |
| 归档不是可读的 ZIP | 错误 |
| 条目名违反第 4.2 节 | 错误 |
| `Mod/mod.txt` 缺失 | 错误 |
| 元数据文件缺失 | 警告；按旧版包导入 |
| `spec_version` 缺失 | 警告；按 `1` 处理 |
| `spec_version` 高于读取方支持的版本 | 警告；继续导入 |
| 必需字段缺失或类型不符 | 错误 |
| `version_name` 不符合 `X.Y.Z` | 错误 |
| `version_code` 为负数 | 错误 |
| `license` 存在但 `LICENSE` 缺失 | 警告 |
| `docs[].file` 指向不存在的条目 | 警告；忽略该条目 |
| 嵌套 `Mod/Mod/` | 错误 |
| 同一深度有两个目录含 `mod.txt` | 错误 |

错误即拒绝该包。警告则导入该包，并记录该情形以供展示。

## 11. 版本

`spec_version` 标识格式。本文另行版本化，遵循语义化版本，每个版本记入 `CHANGELOG.md`。

- 新增可选字段，或在不改变行为的前提下调整措辞，格式版本不变。
- 新增必填字段、删除字段，或改变字段含义，格式版本递增。
- 读取方声明自己支持的最高格式版本。声明值更高的包按第 10 节带警告导入。

本文发布之前写出的包，经第 9 节的旧版路径与第 5 节的 `mod.txt` 名称回退，仍可导入。

## 12. 范围之外

本文不定义：

- `mod.txt` 的内部格式，该格式归游戏所有；
- 地图数据，包括 `CustomMapCodeNames.txt`；
- 制作者的工程目录及其工作文件；
- 资源裁剪或其他再分发优化；
- 分发渠道、签名与更新源。
